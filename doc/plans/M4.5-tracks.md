# M4.5-tracks · 户外运动领域：轨迹上传与处理管线实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox syntax.

**Goal:** 用户走完徒步上传 GPX → 建草稿路线 + 轨迹行 → 同步处理（抽稀/高程/爬升/难度/清晰度，复用 `track_service.process_track`）→ 返回 TrackSummary。draft 不进公共路线库；发布/审核机制归 admin 域（留票）。

**Architecture:** 模块化单体优先（[ADR](../notes/2026-11-13-monolith-first.md)）：MVP **同步内联处理**（<500 点纯计算毫秒级，`python-multipart` 已装），系统设计的 Celery + 预签名直传 + 对象存储为规模化方案，留票。GPX 文件落 `backend/uploads/tracks/{uuid}.gpx`，`route_tracks.gpx_object` 存相对路径 key（未来换对象存储时仅替换存取层）。

**Tech Stack:** 新增显式依赖 `python-multipart`（FastAPI multipart 解析，已装未声明）。

## Global Constraints

- 全部测试保持绿色（120 基线）；覆盖率 ≥ 93% 不回退
- 迁移只增不改：从 **0011** 起（当前 head 0010_trip_plans）

- 上传校验：仅 `.gpx` 后缀、≤5MB、gpxpy 可解析、≥2 点；失败 422 不落任何行（先校验后建行）
- draft 路线不出现在 GET /routes（published 过滤回归）；未登录 401
- uploads/ 不进 git（.gitignore）
- Mimosa 门禁：测试凭据走 `register_and_login`；提交前缀白名单
