# AGENTS.md — doc 目录文档规范

本文件定义 `ganluluo/doc/` 下的文档结构、分层归属、归档规则与写作规则。它是 doc 子树的常设指令：任何在本目录下新建、修改或归档文档的动作，都先对照本文件执行。

- 原型活页（当前开发中的界面）放在 `../protype/` 根目录；定稿归档放在 `../protype/V<N>/`，版本规则见 [原型归档规则](#原型归档规则)。
- 设计规范的常设事实（配色令牌、组件清单、图标库）以 `../protype/V<N>/assets/style.css`、`sprite.html` 与该版本 `README.md` 为唯一权威来源，本目录不复制，只链接。

## 分层与唯一归属：一条事实只有一个家

每条事实只写在其职责所在的层；其他位置一律链接过去。

| 层 | 职责 | 不属于这里的内容 |
|---|---|---|
| 本文件（`doc/AGENTS.md`） | doc 子树的常设规则：归档流程、分层、写作规则 | 具体版本的内容清单（→ 各版本 README）、设计决策的理由（→ `notes/`） |
| `doc/notes/` | 设计决策记录（ADR）：为什么这么做、放弃了什么、如何验证 | 已被推翻的临时方案、实施过程流水账；已定稿的决策用现在时描述现状 |
| `doc/spec/` | 常设设计规范：配色与令牌、组件清单、图标库、平台适配对照 | 某个版本独有的临时改动（→ 该版本 README）、决策理由（→ `notes/`） |
| `doc/changelog/` | 版本发布记录：每版新增/变更/移除的清单式说明 | 变更的原因叙述（→ `notes/`）、教程式内容 |
| `doc/tutorial/` | 按序引导 reaching 一个结果的教程（如「如何新增一个原型页」） | 参考性枚举（→ `spec/`）、一次性操作记录 |
| `protype/V<N>/README.md` | 该版本的交付说明：页面清单、设计令牌、打开方式 | 跨版本对比（→ `changelog/`）、规范复述（→ `spec/`，只链接） |
| `doc/plans/` | 模块实现计划（writing-plans 格式：bite-sized TDD 任务、完整代码、命令与预期输出） | 设计理由（→ `notes/`）、需求规格（→ `spec/`） |
| `protype/` 根目录 README | 指向当前活跃版本的链接 + 进行中工作的说明 | 任何会随版本过时的详细内容 |

放置口诀：理由 → `notes/`；规范事实 → `spec/`；版本差异 → `changelog/`；怎么做的教程 → `tutorial/`；某版本的页面与令牌 → 该版本目录自身。

## 原型归档规则

1. **整版归档，快照自洽。** 归档时把该版本全部页面、`assets/`、`README.md` 作为一个不可拆分的快照移入 `protype/V<N>/`。页面间的相对链接（同目录跳转、`assets/` 引用）必须保持可用——不允许只归档部分页面。
2. **版本号递增，只增不改。** `V1` 之后是 `V2`；已归档目录视为冻结快照，不再修改其中文件。发现旧版 bug 时在新版本修复，而不是回改归档。
3. **归档动作三件套。** 每次归档需同时完成：移动快照；在 `doc/changelog/` 新增该版变更记录；更新 `protype/` 根 README 指向新版本。
4. **新版本从最新归档复制起步。** 开始 `V<N+1>` 时从 `V<N>` 复制到 `protype/` 根目录再修改，而不是从零重建；继承的相对链接结构因此保持一致。
5. **命名保持稳定。** 数字前缀页面（`01-`…`10-`）、平台前缀（`h-` 鸿蒙、`a-` 安卓）、对照板（`index.html`、`platforms.html`）、共享资源（`assets/`）这六类命名跨版本沿用；新增页面按相同前缀惯例插入，不重排已有编号。

## 写作规则

- **写现状，不写历史。** 正式文档中不出现「之前 / 现在 / 原来 / 已改为」；变更故事写入 `changelog/`，理由写入 `notes/`。归档快照目录除外——冻结快照本身就是历史。
- **一条事实一个家。** 写之前先问它属于哪一层；在别处只留一行链接。禁止在 `spec/` 复述某个版本 README 的内容，反之亦然。
- **一段一个物理段落。** 用编辑器软换行；代码块、表格、列表保持自身格式。
- **直陈其事。** 写出具体的页面名、文件名、令牌名、类名（如 `.glass`、`--accent`、`08-route-detail.html`），不用「那个玻璃效果」「新的样式」这类指代。
- **决策必须留痕。** 每次方向性调整（如「玻璃效果参数」「图标重设计」）在 `notes/` 记一条 ADR：背景、决定、放弃的替代方案；`changelog/` 只记发生了什么。
- **相对链接，禁止裸文件名。** 引用一律用相对 Markdown 路径（如 `../protype/V1/README.md`），写完后实际点开验证目标存在。

## 检查清单（提交前自查）

- 同一条规则是否在两个地方都出现？用特征词搜索，保留一个家，其余改链接。
- 是否有叙述历史的句子溜进了非 changelog 文档？
- 是否复述了源文件已经权威表达的内容（CSS 变量值、symbol ID 清单）？
- 归档后 `protype/V<N>/` 里的页面双击打开是否还能跳转、样式是否完整？
- `protype/` 根 README 是否指向当前活跃版本？
- 所有相对链接目标是否真实存在？
